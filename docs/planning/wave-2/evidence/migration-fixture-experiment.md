## 1. Scope and non-goals

This planning experiment asks one bounded question: **can historical logical state be migrated deterministically across exact save/schema/content tuples while exposing semantic loss, content orphans, corruption, multi-hop routing, rollback/recovery, attempt lineage, and unsupported downgrade behavior without selecting a physical save encoding?**

In scope:

- exact source/target logical version tuples;
- registered migration-edge/path selection;
- rename, split, removal, semantic unit change, content removal;
- structured semantic-loss and orphan reporting;
- source/target validation;
- copy-on-write rollback on failed target validation;
- corruption rejection and retry from a known-good source;
- multi-hop composition;
- undeclared/incompatible path rejection;
- unsupported downgrade behavior;
- immutable attempt lineage.

Non-goals:

- no file/container/database/save byte format;
- no compression, encryption, storage provider, engine serializer, final persistence API, or engine choice;
- no canonical semantic encoding/hash algorithm;
- no canonical gameplay/content schema;
- no production migration implementation;
- no implementation-readiness authority.

## 2. Constraints, observations, inference, recommendations

### Observed canonical constraints

The Wave 1 foundation says persistent gameplay-authoritative meaning is engine-independent logical state with stable IDs/versioned schemas; persisted accepted outputs/effects use shared ArtifactIdentity/content-package/migration semantics; stable namespace retirement/tombstones prevent semantic-ID reuse; migration evidence remains an open scoped debt; and `PLANNING_EXPERIMENT` work has no production authority.

### Experiment observations

The retained dependency-free Python harness in §5 was executed under Python 3.13.5 on Linux. All **12** declared outcomes were generated by executable validation/routing/transformation checks and matched expectations. Positive paths preserved declared invariants except the two explicit loss events in §8. Negative cases failed closed without selecting a mutated logical source. An injected postcondition fault rolled back to the original T2 source. Re-running T1→T2→T3 reproduced the same complete logical result and ordered loss report.

### Inferences

- Migration authority needs an exact source tuple, exact target tuple, and declared path; a single save integer is insufficient for the exercised compatibility cases.
- Source validation + copy-on-write transform + target validation makes the exercised failures fail closed at the logical-contract layer.
- Silent content deletion/ID reuse is materially less auditable than a stable tombstone/orphan record.
- Committed downgrade is unsafe when forward migration discarded information and no explicit inverse exists.

### Noncanonical recommendations

1. Use `(save_contract_version, schema_set_version, content_package_id)` as the **minimum exercised** routing tuple; extend it if later evidence proves more identities affect persistence meaning.
2. Require registered migration edges. Missing edges fail closed; no best-effort gap traversal.
3. Validate source → transform a copy → validate target → atomically select target; otherwise retain source.
4. Emit structured loss/orphan events and retain attempt lineage.
5. Preserve missing historical content as a stable tombstone/orphan unless reviewed policy requires hard failure or provides an exact replacement.
6. Reject retired semantic-ID reuse.
7. Keep committed downgrade unsupported unless a separately declared inverse satisfies its information requirements.

## 4. Version tuples, graph, and fixture semantics

```yaml
T1: [save.v1, schema.v1, content.pack.a]
T2: [save.v2, schema.v2, content.pack.a]
T3: [save.v3, schema.v3, content.pack.b]
registered_edges:
  - mig.v1-v2: T1 -> T2
  - mig.v2-v3: T2 -> T3
undeclared:
  - T3 -> T2
  - [save.v3, schema.v3, content.pack.a]
```

T1 source:

```json
{
  "player_id": "player:001",
  "display_name": "Ada Lovelace",
  "coins": 17,
  "home_region": "region:old-harbor",
  "inventory": [
    {"slot_id": "slot:1", "item_id": "item:apple", "count": 2},
    {"slot_id": "slot:2", "item_id": "item:obsolete-key", "count": 1}
  ],
  "legacy_hint_seen": true
}
```

`mig.v1-v2` renames `coins`→`wallet_coins` and splits `display_name` only under the explicit experiment rule `first-token/rest`; an absent/unknown rule is rejected.

`mig.v2-v3` converts `wallet_coins`→`wallet_millicoins` by exact integer multiplication ×1000, removes `legacy_hint_seen` with a loss record, and changes `item:obsolete-key` to `tombstone:item:obsolete-key` while retaining slot/count and `orphaned_from`. Target content package B declares `item:obsolete-key` retired; a package that simultaneously marks it live and retired fails as `TOMBSTONE_ID_REUSE`.

Every transform operates on a copy. Source-validation failure returns the original source. Target/postcondition failure returns the original source with `ROLLED_BACK`. Only a validated target is selected.

## 5. Retained runnable reference harness

```python
from copy import deepcopy

T1=("save.v1","schema.v1","content.pack.a")
T2=("save.v2","schema.v2","content.pack.a")
T3=("save.v3","schema.v3","content.pack.b")
T3_BAD=("save.v3","schema.v3","content.pack.a")
BASE={
 "player_id":"player:001","display_name":"Ada Lovelace","coins":17,
 "home_region":"region:old-harbor",
 "inventory":[
   {"slot_id":"slot:1","item_id":"item:apple","count":2},
   {"slot_id":"slot:2","item_id":"item:obsolete-key","count":1}],
 "legacy_hint_seen":True}

CONTENT_PACKS={
 "content.pack.a":{"live":{"item:apple","item:obsolete-key"},"retired":set()},
 "content.pack.b":{"live":{"item:apple"},"retired":{"item:obsolete-key"}},
 "content.pack.b-reuse-bug":{"live":{"item:apple","item:obsolete-key"},"retired":{"item:obsolete-key"}}}
REGISTERED_TUPLES={T1,T2,T3}
EDGES={(T1,T2):"mig.v1-v2",(T2,T3):"mig.v2-v3"}

def common(s):
    slots=[x.get("slot_id") for x in s.get("inventory",[])]
    if len(slots)!=len(set(slots)): return "DUPLICATE_SLOT_ID"
    if any(not isinstance(x.get("count"),int) or isinstance(x.get("count"),bool) or x["count"]<0 for x in s.get("inventory",[])): return "INVALID_COUNT"

def v1ok(s):
    e=common(s)
    if e: return e
    return None if isinstance(s.get("coins"),int) and not isinstance(s.get("coins"),bool) and s["coins"]>=0 else "INVALID_COINS"

def v2ok(s):
    e=common(s)
    if e: return e
    if not isinstance(s.get("wallet_coins"),int) or isinstance(s.get("wallet_coins"),bool) or s["wallet_coins"]<0: return "INVALID_WALLET_COINS"
    if "display_name" in s or "coins" in s: return "OLD_FIELD_REMAINS"

def pack_ok(pack_id):
    p=CONTENT_PACKS.get(pack_id)
    if not p: return "UNKNOWN_CONTENT_PACKAGE"
    if p["live"] & p["retired"]: return "TOMBSTONE_ID_REUSE"

def v3ok(s,pack_id="content.pack.b"):
    e=common(s) or pack_ok(pack_id)
    if e: return e
    if not isinstance(s.get("wallet_millicoins"),int) or isinstance(s.get("wallet_millicoins"),bool) or s["wallet_millicoins"]<0: return "INVALID_WALLET_MILLICOINS"
    if s["wallet_millicoins"]%1000: return "NONEXACT_UNIT_CONVERSION"
    if "legacy_hint_seen" in s or "wallet_coins" in s: return "OLD_FIELD_REMAINS"

def m12(s,rule="first-token/rest"):
    e=v1ok(s)
    if e: return ("REJECTED_SOURCE",e,deepcopy(s),[])
    if rule is None: return ("REJECTED_POLICY","MISSING_NAME_SPLIT_RULE",deepcopy(s),[])
    if rule!="first-token/rest": return ("REJECTED_POLICY","UNKNOWN_NAME_SPLIT_RULE",deepcopy(s),[])
    out=deepcopy(s); out["wallet_coins"]=out.pop("coins")
    parts=out.pop("display_name").split(" ",1)
    out["given_name"]=parts[0]; out["family_name"]=parts[1] if len(parts)>1 else ""
    e=v2ok(out)
    return ("ROLLED_BACK",e,deepcopy(s),[]) if e else ("APPLIED","OK",out,[])

def m23(s,inject_fault=False,target_pack="content.pack.b"):
    e=v2ok(s)
    if e: return ("REJECTED_SOURCE",e,deepcopy(s),[])
    out=deepcopy(s); loss=[]
    out["wallet_millicoins"]=out.pop("wallet_coins")*1000
    if "legacy_hint_seen" in out:
        pv=out.pop("legacy_hint_seen")
        loss.append(("legacy_hint_seen","REMOVED_FIELD",pv,False))
    for row in out["inventory"]:
        if row["item_id"]=="item:obsolete-key":
            row["orphaned_from"]="item:obsolete-key"
            row["item_id"]="tombstone:item:obsolete-key"
            loss.append((f"inventory[{row['slot_id']}].item_id","CONTENT_ORPHAN_TOMBSTONED","item:obsolete-key",True))
    if inject_fault: out["wallet_millicoins"]+=1
    e=v3ok(out,target_pack)
    if e:
        kind="REJECTED_TARGET_PACKAGE" if e in ("UNKNOWN_CONTENT_PACKAGE","TOMBSTONE_ID_REUSE") else "ROLLED_BACK"
        return (kind,e,deepcopy(s),[])
    return ("APPLIED_WITH_LOSS" if loss else "APPLIED","OK",out,loss)

def route(src,dst):
    if dst not in REGISTERED_TUPLES:
        return ("REJECTED_POLICY",f"UNREGISTERED_TARGET_TUPLE_{dst[1]}_{dst[2]}")
    if (src,dst) in EDGES: return ("DIRECT",[EDGES[(src,dst)]])
    q=[(src,[])]; seen={src}
    while q:
        node,path=q.pop(0)
        for (a,b),eid in EDGES.items():
            if a==node and b not in seen:
                np=path+[eid]
                if b==dst: return ("MULTI_HOP",np)
                seen.add(b); q.append((b,np))
    q=[dst]; seen={dst}
    while q:
        node=q.pop(0)
        for (a,b),eid in EDGES.items():
            if a==node and b not in seen:
                if b==src: return ("UNSUPPORTED_DOWNGRADE",f"NO_DECLARED_INVERSE_{src[1]}_{dst[1]}")
                seen.add(b); q.append(b)
    return ("REJECTED_POLICY",f"NO_DECLARED_PATH_{src[1]}_{dst[1]}")

def migrate(src,dst,state,rule="first-token/rest",inject_fault=False,target_pack_override=None):
    rr=route(src,dst)
    if rr[0] in ("REJECTED_POLICY","UNSUPPORTED_DOWNGRADE"):
        return (rr[0],rr[1],deepcopy(state),[])
    out=deepcopy(state); loss=[]
    for eid in rr[1]:
        res=m12(out,rule) if eid=="mig.v1-v2" else m23(out,inject_fault,target_pack_override or dst[2])
        if res[0] not in ("APPLIED","APPLIED_WITH_LOSS"):
            return (res[0],res[1],deepcopy(state),[])
        out=res[2]; loss.extend(res[3])
    return ("APPLIED_WITH_LOSS" if loss else "APPLIED","OK",out,loss)

r12=migrate(T1,T2,BASE); r13=migrate(T1,T3,BASE)
corrupt=deepcopy(BASE); corrupt["inventory"].append({"slot_id":"slot:2","item_id":"item:apple","count":1})
cases=[
 ("F01",migrate(T1,T2,BASE)[:2],("APPLIED","OK")),
 ("F02",migrate(T2,T3,r12[2])[:2],("APPLIED_WITH_LOSS","OK")),
 ("F03",migrate(T1,T2,BASE,rule=None)[:2],("REJECTED_POLICY","MISSING_NAME_SPLIT_RULE")),
 ("F04",migrate(T1,T2,BASE,rule="first-token/rest")[:2],("APPLIED","OK")),
 ("F05",migrate(T1,T2,corrupt)[:2],("REJECTED_SOURCE","DUPLICATE_SLOT_ID")),
 ("F06",migrate(T2,T3,r12[2],inject_fault=True)[:2],("ROLLED_BACK","NONEXACT_UNIT_CONVERSION")),
 ("F07",migrate(T2,T3,r12[2])[:2],("APPLIED_WITH_LOSS","OK")),
 ("F08",migrate(T3,T2,r13[2])[:2],("UNSUPPORTED_DOWNGRADE","NO_DECLARED_INVERSE_schema.v3_schema.v2")),
 ("F09",route(T1,T3),("MULTI_HOP",["mig.v1-v2","mig.v2-v3"])),
 ("F10",migrate(T2,T3,r12[2],target_pack_override="content.pack.b-reuse-bug")[:2],("REJECTED_TARGET_PACKAGE","TOMBSTONE_ID_REUSE")),
 ("F11",("APPLIED" if migrate(T1,T3,BASE)==r13 else "MISMATCH","OK"),("APPLIED","OK")),
 ("F12",migrate(T2,T3_BAD,r12[2])[:2],("REJECTED_POLICY","UNREGISTERED_TARGET_TUPLE_schema.v3_content.pack.a")),
]
for fid,actual,expected in cases:
    assert actual==expected,(fid,actual,expected)
    print(fid,*actual)
print("SUMMARY",len(cases),"expected outcomes matched")
```

## 7. Multi-hop, rollback, recovery, and downgrade findings

T1→T3 is admitted only through `[mig.v1-v2, mig.v2-v3]`. F09 mechanically proves route selection; F11 reruns the composition and compares the complete returned logical state and ordered loss report.

F05 rejects a corrupt source before transformation. F06 injects a post-transform invariant violation and the migration driver returns the unchanged T2 source. F07 retries from that known-good T2 source without the injected fault and succeeds. This distinguishes:

- **source recovery:** select a separately retained known-good checkpoint after source validation rejects corruption;
- **transaction rollback:** retain the current valid source when transform/target validation fails before commit.

F08 demonstrates that a forward path does not imply an inverse. Because T2→T3 intentionally discards `legacy_hint_seen`, T3→T2 is `UNSUPPORTED_DOWNGRADE` absent an explicit inverse and retained information.

## 8. Semantic loss and orphan report

Successful T2→T3 emits exactly:

```yaml
loss_events:
  - path: legacy_hint_seen
    kind: REMOVED_FIELD
    prior_value: true
    recoverable_after_commit: false
  - path: inventory[slot:2].item_id
    kind: CONTENT_ORPHAN_TOMBSTONED
    prior_value: item:obsolete-key
    recoverable_after_commit: true
```

`legacy_hint_seen` is real semantic loss in this fixture. The removed content item is not silently deleted: slot/count/original identity survive under a tombstone. `wallet_coins=17`→`wallet_millicoins=17000` is exact and is not reported as loss. The name split is lossless only relative to the named fixture rule and this test value; it is not proposed as a universal real-name policy.

## 10. Alternatives

| Alternative | Benefit | Risk | Disposition |
|---|---|---|---|
| Single monotonic save integer | Simple | Hides schema/content compatibility combinations | Reject for authoritative routing. |
| Best-effort unknown migration gaps | Fewer hard failures | Silent semantic corruption/provenance loss | Reject. |
| Hard-fail every missing content item | Strong integrity | Blocks recoverable historical state even when identity can be preserved | Keep as class-specific policy, not default for this fixture. |
| Stable tombstone/orphan | Preserves identity/count and auditability | Requires later UX/recovery policy | Recommended candidate. |
| Retain every historical package forever | Potential exact interpretation | Storage/rights/availability burden | Deferred/evidence-dependent. |
| Automatic down-migration | Convenience | Irreversible loss, absent inverse semantics | Reject unless reviewed inverse exists. |
| Choose physical save encoding now | Enables storage benchmarks | Premature lock-in; out of scope | Explicit non-goal. |

## 11. Dependencies, interfaces, observability

Authoritative task input is the canonical Wave 1 foundation; canonical Planning Program v1 is used only for workflow routing. Canonical schema/content-package/migration semantics remain technical-runtime-owned. This task does not consume or supersede W2-HASH-01 semantic-hash authority. `W2-REV-01` is the declared downstream review.

A future executable migration mechanism should durably expose per attempt: exact source/target tuple; registered path/edge IDs; source checkpoint/ArtifactIdentity when retained; source validation; transform/policy version; target validation; commit/rollback decision; structured loss/orphan events; parent attempt; manual intervention; unsupported path/downgrade result; recovery source after corruption. Aggregate success rate must not hide loss, corruption, rollback, or unsupported downgrade.

## 12. Failure modes and risks

1. **Implicit tuple compatibility** → register full tuples/edges.
2. **Silent semantic loss** → typed loss events + target invariants.
3. **Orphan laundering** → tombstone original ID; forbid retired-ID reuse.
4. **Retry laundering** → immutable parent-linked attempts.
5. **Partial source mutation** → copy-on-write + validate before selection.
6. **False downgrade support** → explicit inverse edge required.
7. **Direct-path drift versus historical hops** → version path; prove equivalence for any claim needing it.
8. **Physical-format leakage** → keep this evidence logical/nonproduction.
9. **Scale/performance blind spot** → separate large-save benchmark evidence.
10. **Fixture-policy overgeneralization** → keep name split and content rules fixture-scoped.
11. **Single-reference-harness correlation** → independent review must not treat this as cross-runtime equivalence evidence.

## 13. Unresolved questions and reopen conditions

Unresolved:

- Which additional identities, if any, belong in real Everfield persistence tuples?
- Which physical storage/atomic-commit mechanism should realize logical copy-on-write?
- Which orphan classes tombstone versus hard-fail/quarantine?
- How long must old packages/checkpoints remain available and under what rights/retention policy?
- What repair/diagnostic UX is acceptable after loss?
- What scale/performance targets apply?
- Which migrations require independent cross-runtime equivalence evidence?

Reopen if a reviewed runtime schema makes the three-part tuple insufficient; loss can be hidden; retired IDs can be reused; retry/recovery can overwrite the only known-good source; direct/multi-hop paths disagree for a claim requiring equivalence; a claimed inverse loses data; real persistence mechanics invalidate the atomicity model; W2-REV-01 finds BLOCKER/MAJOR; or later work attempts to treat this single-harness result as production migration proof.

## 14. Required independent critique and downstream work

`W2-REV-01` must independently attack at least:

**Author conclusion:** `BOUNDED_PASS` only for the stated logical-contract experiment. The evidence supports carrying explicit tuple/path/loss/orphan/rollback/lineage requirements into independent Wave 2 review. It does **not** select a physical save encoding, make migration architecture canonical, resolve implementation-readiness blockers, or authorize production implementation.
